Demander une installation Page IA pour mairie

Côté DSI

Quatre étapes. Une VM.

Docker et Docker Compose doivent déjà être sur la machine. Le script ne les installe pas : il s’arrête s’ils manquent.

01

Une VM Linux

C’est le serveur de la collectivité. L’application n’est pas un logiciel à poser sur chaque poste.

02

Le script d’installation

Il charge l’image Docker livrée (fichier .tar) et démarre l’application avec Docker Compose. Le port par défaut est 3000, puis l’adresse interne de la mairie.

03

La clé de la mairie

Une clé, dans les réglages, pas une par agent. Mistral peut être choisi pour une question de RGPD : hébergement européen, contrat de la collectivité. Le logiciel prend aussi en charge Claude, ChatGPT, ou un modèle local. STELLARMEET ne garde pas les échanges. L’usage d’une API est facturé par le fournisseur, sur le compte de la mairie. ChatGPT n’est pas présenté ici comme un service hébergé en Europe.

04

Ollama, si pas d’API externe

Une seconde VM peut porter les modèles locaux. Le script peut installer Ollama sous Linux et télécharger les modèles : comptez plusieurs minutes. Les questions restent sur cette VM.

Plafond journalier

  • Le quota du compte (Mistral, Claude, ChatGPT ou un autre) est réparti automatiquement.
  • Un plafond journalier est calculé pour chaque agent.
  • Il suit le quota réel, pour qu’un agent ne brûle pas le quota de la collectivité.

Ce que les agents ouvrent

La base, le web, l’intranet.

Base de connaissance

STELLARMEET tient à jour le socle métier : droit territorial, RH, urbanisme, marchés, finances. Des agents cadrent la réponse, de la délibération au RIFSEEP, au PLU, au MAPA, à la DGF. La mairie y dépose ses propres pièces. Les actes d’autres communes s’ajoutent par import : le stock local n’est pas livré prérempli.

Moteur de recherche

Une question interroge le web et la base en même temps. La recherche web ne remplace pas les notes, les règlements ni les actes indexés. L’agent relit avant d’agir.

Actualités de la collectivité

Le fil est rangé pour une mairie : État, droit, finances locales, RH, urbanisme, marchés, environnement, numérique, et son territoire. Ce n’est pas un flux généraliste.

Intranet de publication

Inclus dans la licence. La communication publie règlements, notes et accueil des agents. Rubriques prévues : accueil, règlements, RH, bâtiment, vie des services. Un article publié entre dans la base et peut être cité dans la réponse.

Chaque matin

Le récap est déjà composé.

L’écran d’accueil croise l’actualité de la collectivité, les pièces de la base de connaissance, et les articles publiés sur l’intranet. L’agent n’a pas à ouvrir un outil par sujet.

  1. L’actualité du territoire et des textes qui le concernent.
  2. La base : métiers tenus par l’éditeur, pièces déposées par la mairie.
  3. L’intranet : ce que la communication a publié pour les agents.

Où vont les données

Le dossier reste à la mairie.

STELLARMEET fournit le logiciel, le maintient à jour et assure le support. Les conversations et les fichiers des agents restent sur le serveur de la collectivité : STELLARMEET ne les conserve pas.

Le poste

L’agent pose sa question dans le navigateur, sur l’adresse interne.

Le serveur

Comptes, conversations, base de connaissance et intranet restent dans le volume Docker de la DSI.

Le modèle

La clé est celle de la mairie. Mistral peut être choisi pour le RGPD (hébergement européen, contrat de la collectivité). Claude, ChatGPT ou un autre modèle sont possibles si la DSI en a besoin. Ce site ne promet pas que ChatGPT est hébergé en Europe. Sur une VM Ollama, le texte reste en local.

Le détail est dans la politique de confidentialité et le DPA.
