Installation par la DSI

Le script d’installation s’arrête si Docker n’est pas déjà là

12 novembre 2026 · TerritoIA, édité par STELLARMEET

Si Docker n’est pas installé sur la VM, le script d’installation s’arrête. Il n’installe pas le moteur à la place de la DSI. La reprise se fait quand Docker est là, vérifié, et que le droit de lancer un conteneur est clair.

Arrêt propre

L’arrêt n’est pas une panne à contourner. La DSI lit le message, elle installe Docker selon sa propre procédure, elle relit que le service démarre au boot, puis elle relance le script. On ne colle pas une image « pour voir » sur une machine sans moteur.

Pourquoi ce choix

La collectivité garde la main sur le socle. Une installation silencieuse de Docker mélangerait la responsabilité de l’éditeur et celle de la DSI. Ici, la frontière est écrite : le script pose TerritoIA, pas le système.

Après la reprise

Une fois Docker présent, la DSI note la version dans le journal. Les agents n’interviennent pas. L’adresse reste interne. Ce n’est pas un accueil des habitants. Le maire ne signe rien à cette étape.

La DSI vérifie aussi que le disque du démon Docker est bien celui prévu pour les volumes, et pas un disque temporaire. Elle relit le chemin. Une mise à jour ultérieure ne doit pas écrire ailleurs sans qu’on l’ait vu.

La DSI vérifie aussi que le démon ne tourne pas en root négligé sur une machine partagée avec un autre applicatif critique. TerritoIA a sa VM. Mélanger le conteneur avec la messagerie ou le logiciel financier « pour économiser une machine » se discute à part, et se refuse si la sauvegarde et les droits ne sont plus lisibles. Elle relit le nom de la VM le matin de l’installation.

Le droit de parler au moteur Docker se limite aux administrateurs nommés. Un agent du secrétariat n’a pas ce droit, même s’il est curieux et même s’il a un compte sudo ailleurs « pour dépanner l’imprimante ». La DSI relit le groupe. Un ajout temporaire pour une démo se retire le soir même, et elle le note.

Si le script s’est arrêté, la DSI ne le relance pas en boucle en espérant un autre message. Elle traite la cause, puis un seul nouvel essai. Le support peut expliquer l’arrêt. Il n’installe pas Docker à distance et il ne demande pas le mot de passe de la VM. Les habitants ne sont pas concernés. Le maire ne signe rien. L’agent, plus tard, relira ses textes : cette étape-ci ne produit encore aucune réponse métier.

Elle note la version de Docker à côté du nom de la VM, et elle la revérifie après les mises à jour du système. Un démon qui ne redémarre plus au boot se voit le matin, pas pendant un conseil. La DSI relit le service au boot une fois, exprès.
